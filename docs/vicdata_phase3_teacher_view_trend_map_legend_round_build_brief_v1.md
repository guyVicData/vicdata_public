## The dark-basemap question, answered

No dark tile variant exists anywhere in the real code. `AcademicMapView.tsx`'s `TILE_URL` points at CARTO's `light_all` basemap unconditionally (`https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png`), used exactly as-is even when the rest of the app is in dark theme — there's no dark-tile URL, dark-tile toggle, or theme-aware tile switch anywhere in `SchoolMap.tsx`, `MapView.tsx` or `AcademicMapView.tsx`. So the map surface is, deliberately or not, the one light rectangle inside an otherwise dark UI, in the real product today. Per Guy's own fallback ("if not, continue as it is"), the wireframe needs no change here.

## What this checked first, and what it found

Before scoping any code, checked the real repo — `vicdata_public` at `dff9ec0` (the commit the just-pushed comparator-chooser build report left `main` at); `vicdata`'s separate migrations repo, checked at its own `3a37efb`, a different repository with its own history, unrelated to this round beyond the subject-family SQL cited below — against what Round 10's wireframe had assumed. The headline finding: **most of what this round's mockup shows is already shipped**, more of it than the wireframe's own working notes had assumed. Specifically:

- **The multi-subject Trend chart is already real.** `SubjectPanels.tsx`'s `trend` panel (`redesigned = changeScope !== "all"`, line 192) draws History plus every real GCSE category peer as individual, always-visible lines when Column 1 passes `changeScope="individual"` — which it already does, at `src/app/teacher/[phase]/page.tsx:1562`. Nothing to build here; the mockup was built to depict this correctly.
- **The table's sort arrows are already real.** `SeriesViews.tsx`'s `YearTable`, in its own `head()` helper (lines 316-329), already renders a `▲`/`▼` beside every clickable column header, at `opacity-0` unless that column is the active sort key, full opacity and the correct direction when it is. Rank is already the default sort (`useState({ key: showRank ? "rank" : "given" })`, line 275). Guy's "add sort arrows... plus indicate which is the current sort" is already shipped, in full — nothing to build for `FullscreenTable.dc.html` either.
- **The footer "Trend Line" toggle is already real**, not a new control: `SubjectPanels.tsx:488-495` already passes a `TrendLineToggle` (`PanelFooter.tsx:234`) as the trend panel's `footerLead`, grey/inactive by default, disabled when there's no line to fit. The mockup's footer button was corrected to this real copy and behaviour last round; no code change follows from it.
- **The fullscreen side rail (flag + private note) is already real**, and newer than expected: `CardBox.tsx`'s fullscreen modal (built in the accordion round's Part 4) already renders a narrow `<aside>` to the right of the main content — a "Flag" section, then a "Your note · private" section — whenever the panel passes a `flag` or a `note` (`CardBox.tsx:363-386`). So this round doesn't invent a rail; it adds a new section to the TOP of one that's already shipping, and reorders what's already there underneath it.
- **A real map for a subject/category, with the exact bivariate encoding Guy described, is already shipped — for a different column.** `components/teacher/RankingsMap.tsx` mounts `AcademicMapView.tsx` directly (`dense={false}`) as Column 3's own real Comparisons/Rankings fullscreen map, and it already accepts `subject`, `subjectLabel`, `subjectBucket` and `familyId` props to plot one named subject's own figures rather than the whole school (`RankingsMap.tsx:24-40`). It is wired into `ComparisonsPanels.tsx:308` only — Column 1's Trend panel has never received it. Real facts confirmed by reading `AcademicMapView.tsx` directly: CARTO Positron light tiles (above); Leaflet's own default `L.control.zoom({position:"bottomright"})`, unstyled beyond position (line 751); sqrt-scaled dot radius (`MIN_RADIUS=5, MAX_RADIUS=20`, lines 82-83, 104-106); colour by `gradeBandColour`/`gradeBandColourForFamily` (sequential, darker = higher) or `trendColour` (red–amber–green) depending on a real "Grade band"/"Trends" toggle (lines 1213-1229); a real `GradeBandColourKey` that **already draws exactly three labels — max, the true midpoint, and min** (`AcademicMapView.tsx:245-273`: `labelStops = [{t:0,value:max},{t:0.5,value:mid},{t:1,value:min}]`), in a 26px-wide gradient bar. Guy's own instinct this round — "add middle value to scale: 5.5" — turns out to match this real component's own three-label shape exactly; that wasn't known when the instruction was given, and is worth saying back to him. The real tooltip copy (bold entries count + bold avg. point score, each dated, "(this school)" on the target), on hover via `bindTooltip({direction:"top"})`, is confirmed at `AcademicMapView.tsx:954-958`.
- **The map's own school-profile data is already loaded page-wide, not fetched per column.** `page.tsx` fetches `mapProfiles` once (`~line 182`, `setMapProfiles` at `~line 332`, from `/api/data-view/academic-schools`) and passes it down; today only `ComparisonsPanels.tsx:309` (`profiles={mapProfiles}`) consumes it. Adding a map to Column 1's Trend panel needs this same prop threaded one level further, not a new fetch.
- **No real precedent exists for hiding an individual line.** `TrendChart.tsx`'s legend (`line 329`, `flex flex-wrap gap-x-3.5 gap-y-1`) is a static list of coloured labels; `MultiTrend` (`SeriesViews.tsx:56-111`) always draws every series in `data.series`. Guy's "tick boxes... to turn off or on lines" is genuinely new — there's nothing to make the mockup more accurate to here, because nothing like it exists yet.

## What's actually new in this round

Four things follow from the gap above; everything else the mockup shows is either already shipped (no code needed) or a pure layout/reorder change to something already shipped:

1. **A per-subject show/hide toggle on Trend**, replacing the static legend with the combined coloured-checkbox row the mockup already shows (`Fullscreen.dc.html`'s `.legend-check` rows — one element, not a separate dot and a separate box, per Guy's own "interface overkill" call). New client state in `SubjectPanels.tsx` (`hiddenKeys`), filtering `trendData.series` before it reaches `MultiTrend`/`YearTable`. History stays permanently ticked and un-clickable, exactly as the mockup's `checked disabled` row shows — Guy's own note confirms this: "subjects shown should all be ticked in this mockup as all showing on the graph."
2. **A `legend` slot added to the fullscreen rail**, above the existing flag/note section, with a divider between the two groups — a small, additive change to `PanelRender` (`ColumnPanels.tsx:34`) and `CardBox`'s own props and fullscreen `<aside>` (`CardBox.tsx:172`, `:363-386`), not a new rail.
3. **A Map view added to Column 1's Trend panel** as a third `actions` icon alongside Chart/Table (`SubjectPanels.tsx:495-506`), reusing `RankingsMap`/`AcademicMapView` exactly as Column 3 already does, scoped to History's own subject/family (mirroring `RankingsMap`'s existing `subject`/`subjectLabel`/`subjectBucket`/`familyId` props) rather than the whole school. `mapProfiles` threads one level further from `page.tsx`; no new fetch.
4. **The new map's own chrome**, matching the real `AcademicMapView` conventions confirmed above, with three of Guy's own explicit layout calls layered on top: mode buttons top-right; a horizontal, headinglesss dot-size box bottom-left (a deliberate simplification — the real `SizeLegend`, `AcademicMapView.tsx:284`, keeps its "Dot size" title; Guy's own instruction drops it for this board specifically); a vertical grade-band/trend colour bar, same 26px width as the real `GradeBandColourKey`, positioned midway between the zoom control and the mode buttons rather than the real per-corner stack — a genuine layout deviation from the real product, made on Guy's own explicit instruction, not a grounding gap.

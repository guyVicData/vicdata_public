## Part 4 — hide the Map, add rank-in-set tiles, for a ranking-type comparator

**Where:** `src/lib/chooser-sets.ts` (`resolveRankingSet`, and whatever the resolve endpoint returns to the frontend), `src/components/teacher/ComparisonsPanels.tsx` (`SetOption` type, `~line 70`; the `view` state and its Map/Ranking/Graph icons, `~line 204` and `~line 293-295`).

**What to add:**

1. Thread a `kind`/`isRanking` discriminant from the server's resolve step through to the frontend's active-set info — today `SetOption` (`id`/`label`/`group`/`meta`/`editable`) has no such field, and it's the only place `ComparisonsPanels` learns about the active set. This is the actual gap blocking everything else in this part: without it, the component has no way to know the active set is a ranking rather than a nearest/LA/custom list.
2. Alongside it, thread `resolveRankingSet`'s already-computed `targetRank`/`matched`/`ranked` through to the frontend — this is the exact "school's rank in that set" figure item 4 asks for, already computed server-side (`chooser-sets.ts:98`); it just isn't reaching the component that would display it today.
3. Add a genuine population-average figure to `resolveRankingSet`'s return. Its current return (`rows`, narrowed to top-15-plus-5 around the target) is a deliberately skewed sample, not representative of the set as a whole — averaging it would misrepresent "the set's average." Compute the true mean over the full matched population (`cachedRankingPopulation`'s own result, before narrowing) and return it as a new field.
4. In `ComparisonsPanels.tsx`: when the active set's kind is a ranking, hide the `MapPinIcon`/Map view entirely (not just grey it out — item 4 says "no map view for these"), and default `view` to a new `"tiles"` state instead of `"map"`. Build this tiles view by reusing Part 2's generic tiles component (main figure = the school's own headline value; subsidiary figure = rank-in-set, from `targetRank`/`ranked`, using the same icon-beside-core-figure-then-one-line-underneath layout Part 2 established — e.g. icon + "12th", then "of 340 in this set") rather than a second, similar-but-separate component.
5. The remaining Graph view, when a ranking is active, should plot the school's own value against the new population-average figure from step 3 — not against the individual narrowed comparator rows the Graph view plots today for a nearest/LA/custom set. Check whether this is a genuinely different chart (school vs one average line) or a filtered mode of the existing graph component before deciding whether to branch the component or extend it.

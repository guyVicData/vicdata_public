# Move VRQ into the BTec & OCR bucket — and a real data-quality problem this surfaced

## Why

A live review of Capital City College (URN 130421) traced a real family's own experience against the real data. Guy's children did what the family calls "a BTEC in Fine Art" there — one currently studying there now. The real DfE data confirms substantial, ongoing Art & Design vocational provision every year 2021–2024 (36 entries in 2021, 20 in 2022, 25–31 in 2023, 22–27 in 2024) — but DfE's own dataset classifies it as **`VRQ Level 3`**, not any Pearson-branded BTEC qualification type. Real Pearson BTEC Art & Design at this school is a single entry, one student, 2021 only ("Multimedia") — clearly not the real course. VRQ is DfE's own catch-all label for Level 3 vocational awards outside the specifically-tracked BTEC/OCR Cambridge Technical cohorts — plausibly covering things like a UAL Diploma/Extended Diploma in Art & Design here, which is exactly the kind of course a family reasonably calls "a BTEC," even though DfE's own taxonomy files it separately.

The qualification-bucket round put VRQ into `other`, not `btec_ocr`, for a real, defensible reason: VRQ genuinely spans non-comparable qualification sizes under one DfE label (documented in the original Haverstock School/URN 100049 investigation). That's still true. But it means a substantial, ongoing, everyday-recognizable-as-"a BTEC" course is invisible under the pill anyone would click first, and only shows up in "Other," which carries no headline points figure and isn't where anyone would think to look.

**Decision (confirmed with Guy): move VRQ into `btec_ocr`.** This brief covers what that actually requires — it's more than a one-line bucket reassignment.

## A real, previously undiscovered data-quality problem, found while scoping this

Checking VRQ's real grade vocabulary platform-wide (not just Art & Design) before writing this brief turned up something worth flagging on its own, separate from the bucket move: VRQ's real "size" field (segment 3 of the `qualification::subject::size::grade` breakdown, normally a numeric `a_level_equivalent_size` like `0.5`/`1`/`1.5`) contains, for a real subset of rows, values that are plainly not sizes at all — `A`, `B`, `C`, `D`, `F`, `M`, `P`, `U`, `X`, `Total`, `Total exam entries`, `Total number entered`, `Covid impacted`, `Level 2 distinction`, `Level 2 distinction star`, `Level 2 merit`, `Level 2 pass`. That looks like a real column-shift or parsing issue in `dfe_ks5_subject_results(_historic).py` for at least some VRQ source-file layouts, not a one-off. **Investigate this directly before trusting any VRQ size value for a points computation** — this is a separate, real ingest bug this task surfaced, not something to route around silently. If it's confined to specific historic years or file variants, say which; if it affects current-year VRQ rows too, that's more urgent.

## What VRQ's real grade vocabulary actually looks like

Confirmed directly, platform-wide, VRQ Level 2 + VRQ Level 3 combined — this is a genuinely bigger, messier set than BTEC/OCR's:

- Single grades, multiple real label forms for what appears to be the same scale: `Distinction*`/`Distinction`/`Merit`/`Pass` (word form), `A*`/`A`/`B`/`C`/`D`/`E` (letter form), `*`/`D`/`M`/`P` (abbreviated form, VRQ Level 2) — verify which of these genuinely co-occur in the same period the way `A*`/`*` did for A-level (the bug that undercounted 2021–23), and alias accordingly rather than assuming.
- A distinct five-grade scale: `Distinction`/`High merit`/`Merit`/`High pass`/`Pass` (word form) and `HM`/`HP`/`M`/`P` (abbreviated) — confirmed real at Capital City College's own Art & Design entries. Does NOT map onto the existing `VOC_FOUR` table in `dfe-qualification-buckets.ts` — a new table, if a real DfE source for it exists.
- Paired and tripled combination grades (`Distinction-Merit`, `MM`, `Distinction*-Distinction*-Distinction`, `DDM`, etc.) — these likely DO match the existing `VOC_SEVEN`/`VOC_TEN` tables already built for BTEC/OCR; confirm rather than assume, since VRQ's tripled set includes combinations (`Distinction*-Distinction*-Distinction*` = `***`) not currently in `VOC_TEN`.
- Real non-grade markers that must never be scored as if they were grades: `COVID result`, `No result`, `No result / X`, `Suppressed`, `Supp`. Research what each really means before deciding how to treat it — `COVID result` looks like a real, countable entry with a pandemic-era substitute outcome that can't be honestly scored (same shape as T Level's "Partial achievement" — count it, don't score it); `No result`/`No result / X` may mean something closer to "did not complete," which might mean NOT counting it as an entry at all. Don't guess; check what DfE's own documentation for these source files says, or how the ingest already treats an analogous marker elsewhere if one exists.

## What to actually build

1. **Move `VRQ Level 2` and `VRQ Level 3` from `other` to `btec_ocr`** in `bucketFor()` — both twins, `dfe-qualification-buckets.ts` and `dfe_points.py`. They must stay in agreement, as everywhere else in this bucket system.
2. **Entries and subject visibility come first and don't wait on the points question.** Once the bucket reassignment lands, VRQ entries should immediately count toward `bucket:btec_ocr::entries` and show up in the BTec & OCR subject list for any category — this alone fixes the real, immediate problem Guy found. Verify directly: Capital City College's Art & Design VRQ entries (22–27 in 2024) should now appear under BTec & OCR in that category.
3. **Points are the harder, separate question — do not rush this.** Investigate whether DfE's "Performance points: a practical guide" publishes a real challenge table covering VRQ's real grade shapes (the five-grade Pass/High pass/Merit/High merit/Distinction scale especially, since that one clearly doesn't match anything already built). If a real, verifiable table exists for a given shape, compute points for it the same way IB and BTec & OCR were computed last round — verified against a real, independently-known figure before trusting it, not just internal consistency. If no real table can be found or verified for a given VRQ grade shape, or if the size-column data-quality problem above can't be resolved with confidence, those VRQ entries should count toward `entries_total` but be excluded from the bucket's points average — the same "counts toward entries, not toward points" treatment already used for other real cases in this system (dirty BTEC grade codes, T Level's Partial achievement). An honest partial-coverage bucket beats a fabricated or silently wrong one. Report exactly which VRQ grade shapes could and couldn't be scored, and why.
4. **Grade aliasing.** Before scoring anything, confirm which of VRQ's real label variants are genuinely the same grade under a different name (the same discipline that caught the A\*/\* bug) versus genuinely different things. Don't assume symmetry with BTEC/OCR's own alias handling — check VRQ's real co-occurrence patterns directly.
5. **Update the bucket descriptions.** `KS5_BUCKET_DESCRIPTION.btec_ocr` should mention it now includes VRQ, not only Pearson BTEC and OCR Cambridge Technical. `KS5_OTHER_NO_FIGURE_NOTE` currently justifies "Other" having no headline figure by naming VRQ specifically ("VRQ Level 3 alone covers nine different qualification sizes under one DfE label") — that sentence is now wrong and needs rewriting for whatever "Other" contains once VRQ leaves it (EPQ, Core Maths, Free-standing Maths, Pre-U, Other General). If BTec & OCR ends up with a partial-coverage caveat per #3, give it the same kind of visible, honest note "Other" already has, rather than a silent gap.
6. **Recompute and verify.** Same guarded chain as every prior round. Re-run the Capital City College check by hand — confirm the real VRQ Art & Design entries now appear under BTec & OCR, with the right entries count, and either a real computed points figure or an honest "not scored" state, whichever #3 lands on.
